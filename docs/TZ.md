# Техническое задание v1.0
## FloorCam — событийная система видеонаблюдения этажа

### 1. Общие сведения

**Название:** FloorCam
**Тип:** pet-project / self-hosted CV-платформа
**Объект:** коридор этажа многоквартирного дома + зона дверей лифта
**Режим:** событийная запись (event-only) с кольцевым pre-roll буфером
**Правовой статус:** согласие всех собственников, таблички, УК извещена

### 2. Цели

1. Фиксация событий (люди, нарушения, инциденты) без непрерывного архива.
2. Классификация событий и уведомления.
3. Веб-интерфейс управления.
4. ML-контур: дообучение, версионирование моделей, ансамбли, shadow-деплой.

### 3. Scope

**Входит в MVP (MUST):**
- [ ] RTSP-ингест с камеры (основной + субпоток)
- [ ] Кольцевой буфер (pre-roll ≥ 10 с, post-roll ≥ 20 с)
- [ ] Person detection + motion zones
- [ ] Сохранение клипа + snapshots + метаданных события
- [ ] Список событий, фильтры, просмотр клипа
- [ ] Уведомления (Telegram)
- [ ] Авторизация и роли (Viewer / Operator / Admin)
- [ ] Аудит-лог доступа и экспорта
- [ ] Health-check камеры и сервисов

**Вторая очередь (SHOULD):**
- [ ] Tracking (track id, вход/выход из зон, dwell time)
- [ ] Классификация событий (loitering, multi-person, person-near-lift)
- [ ] Review/labeling интерфейс для дообучения
- [ ] Model registry: загрузка весов, версии, откат
- [ ] Shadow mode для новых моделей

**Третья очередь (MAY):**
- [ ] Ансамбли моделей с весами
- [ ] Детекция оставленных предметов, падения, бега
- [ ] Экспорт датасета для обучения
- [ ] Multi-camera поддержка
- [ ] PWA / mobile-friendly UI

**Не входит (OUT OF SCOPE):**
- Распознавание лиц (только как отдельный будущий модуль)
- Аудиозапись
- Съёмка внутри квартир / лифта
- Интеграция с домофоном

### 4. Архитектура

```
IP-камера (RTSP, PoE)
   │
   ▼
Ingestion (go2rtc/FFmpeg) ── ring buffer
   │
   ▼
Detection (YOLO person) ── Tracking (ByteTrack)
   │
   ▼
Zone logic ── Event candidate
   │
   ▼
Classifier / ensemble ── Event Manager
   │
   ├── Storage (PostgreSQL + MinIO/FS)
   ├── Notifications (Telegram/email/webhook)
   └── Web UI / API (FastAPI + React)
```

### 5. Требования к событию

Каждое событие хранит: id, камеру, тип, severity, время start/end,
pre/post-roll, confidence, track_ids, zone_ids, пути к клипу и кадрам,
список моделей с версиями и score, статус разметки, sha256 клипа.

### 6. ML-требования

- Детекция: YOLOv8/v11 (ONNX/OpenVINO/TensorRT), person class.
- Трекинг: ByteTrack/BoT-SORT.
- Классификация: этап 1 — эвристики по трекам; этап 2 — обученный
  классификатор на размеченных событиях.
- Model registry: манифест (task, format, classes, checksum, metrics),
  валидация, shadow mode, откат, журнал.
- Дообучение: review queue → разметка → экспорт датасета → обучение
  оффлайн → деплой новой версии.

### 7. Нефункциональные требования

| Параметр | Цель |
|---|---|
| Live latency (локально) | 0.5–2 с |
| Задержка детекции | ≤ 1–2 с |
| Уведомление после события | ≤ 10 с |
| Хранение событий | ≥ 30 дней |
| Деградация | при падении классификатора события пишутся как unknown |
| Автовосстановление | docker restart + watchdog потоков |

### 8. Безопасность и приватность

- HTTPS, RBAC, аудит; RTSP не наружу; удалённый доступ только VPN.
- Privacy-маски на зоны, не подлежащие съёмке.
- Аудио выключено; срок хранения ограничен; экспорт с журналом.

### 9. Критерии приёмки MVP

1. Камера стабильно в сети, поток восстанавливается после сбоя.
2. Событие «человек» создаёт клип с pre-roll, snapshots и метаданными.
3. Уведомление приходит в Telegram ≤ 10 с.
4. События фильтруются по дате/типу/статусу, клип открывается в UI.
5. Админ может загрузить новую версию модели и откатиться.
6. Все просмотры/экспорты фиксируются в аудит-логе.

### 10. Этапы (оценка для одного разработчика)

| Этап | Срок | Результат |
|---|---|---|
| 0. Камера + Frigate | 1–2 нед | работающее наблюдение |
| 1. Event-сервис + UI | 3–4 нед | своя событийная платформа |
| 2. Классификация | 2–3 нед | event classifier |
| 3. Model registry | 2 нед | MLOps-lite |
| 4. Дообучение | 2–4 нед | active learning loop |
